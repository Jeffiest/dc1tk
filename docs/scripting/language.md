# C Language, SDK, and Patches

Scripts in `dc2tk` use C89 syntax plus a few built-in statements for the game's virtual machine.

## Language basics

- **Built-in types**: `int` (32-bit signed integer), `float` (32-bit float), and `string` (text literal, such as `"Hello"`).
- **Standard C features**: Functions, local and global variables, arrays, pointers (`*p`, `&x`), `struct`, `union`, `enum`, `typedef`, `if`/`else`, `while`, `for`, `do`/`while`, `switch`/`case`, `break`, `continue`, `return`, `#define`, `#include`, and `#if`.
- **Built-in VM statements and functions**:
  - `wait;` — Yield execution until the next frame (1/25 second on PAL).
  - `end;` — Stop the current script program immediately.
  - `skip_end;` — Target label where a skipped cutscene jumps when the player presses Start.
  - `sin(x)` and `cos(x)` — Trigonometric functions (angles in radians).
  - `print(...)` — Debug print instruction.

## C's semantics, and the VM's `(any)`

Every script is C89: a value stored in a variable, passed to one of the script's functions or returned is converted to that type (an `int` stored in a `float` becomes a float, a `float` stored in an `int` is truncated), `&&` and `||` give `0` or `1`, and a native call in an operand C skips (`a && get_flag(5)`) is not made. Two things the game's virtual machine does its own way show up in code:

- **Native arguments go as they are.** `set_bgm_master_volume(1)` passes the int `1`. The engine reads a native's arguments with `GetStackInt` and `GetStackFloat`, which convert as C does, so the native sees `1.0` either way.
- **`(any)` keeps the VM's value.** The VM stores a value with the type it has: an `int` variable can end up holding a float. `(any)x` stores, passes or returns `x` without C's conversion, and `(any)(a && b)` gives the VM's value of `a && b` (the operand that decided it, not `0` or `1`). The decompiler writes `(any)` wherever a retail script relies on this, as in `count = (any)get_rage_hits_left();`, which leaves the float's bits in an `int` (the native writes its result straight into the variable). New code rarely needs it.

`x = 0;` with `x` a `float` stores the int `0`: its bits are `0.0`'s, and every read of a `float` variable treats the slot as a float, so nothing can tell them apart.

## SDK headers

Every script includes the header for its script type from `sdk/`:

- [`<event.h>`](api/event.md) — Town, story map, cutscene, and dungeon scripts.
- [`<monster.h>`](api/monster.md) — Monster and boss AI scripts.
- [`<action.h>`](api/action.md) — Player, monster transform, and Ridepod combat scripts.
- [`<effect.h>`](api/effect.md) — Visual and hitbox effect scripts.
- [`<arg.h>`](api/arg.md) — Event argument scripts.

Two additional headers provide named constants:

- `<pal.h>` — Named save flags (`FLAG_...`), sound banks (`SE_...`), and music tracks (`BG_...`).
- `<disc.h>` — Generated by `dc2tk setup` from your disc. Defines every monster kind (`MONSTER_GOLEM`), item (`ITEM_BREAD`), NPC (`NPC_GORDON`), character motion, and effect name.

## Value kinds

In the [API Reference](api/README.md), many parameters use descriptive **value kind** typedefs such as `monster_kind`, `item_id`, or `bgm_file`. These compile as plain `int` or `string` values and tell the decompiler and editor which constants from `<disc.h>` or `<pal.h>` belong in each parameter.

## modkit

`sdk/modkit/` provides small C helper libraries that any mod script can include:

```c
#include "modkit/text.c"
#include "modkit/input.c"
```

- **`"modkit/text.c"`**:
  - `modkit_say("Hello!")` — Shows a message in window `0`, waits for the player to press `(X)` or `(O)`, and closes the window.
  - `modkit_caption("Wave 1")` — Shows a non-blocking banner at the top of the screen during gameplay, or closes it when passed `""`.
  - `modkit_text_number(0, 1, score)` — Sets `[Number1]` before showing a message.
- **`"modkit/input.c"`**:
  - `modkit_wait(frames)` — Waits `frames` frames (`25` frames = 1 second on PAL).
  - `modkit_button_pressed(PAD_CROSS)` — Returns `1` on the frame a button is newly pressed.
- **`"modkit/tick.c"`**:
  - `modkit_tick(flag, frames, program)` — Runs a map program every `frames` frames from a monster script during combat (used in [Show live captions during a fight](tutorials/captions.md)).
- **`"modkit/math.c"`**: Common math helpers (`modkit_abs`, `modkit_min`, `modkit_max`, `modkit_clamp`).

For all functions, see the [`modkit` API Reference](api/modkit.md).

## Patching scripts in a mod

Instead of copying an entire game script into your mod, write a short **patch** `.c` file in `mods/<your-mod>/`.

Generate a starter patch with `dc2tk mod override`:

```sh
dc2tk mod override extracted/scripts my-mod --map s51 start_castle_battle
```

Or write the patch file directly:

```c
#pragma target map s51          // Apply to map s51 (all 5 PAL languages)
#include <event.h>
#include <disc.h>

NEW_FLAG(CASTLE_MOD_ACTIVE);    // Allocate a free save flag

#pragma override                // Replace start_castle_battle in the target script
void start_castle_battle(void)
{
    original();                 // Call the original function from the game
    set_flag(CASTLE_MOD_ACTIVE, 1);
}
```

- **`#pragma target`**: Selects which scripts to patch:
  - `#pragma target map s51` — All 5 language variants of map `s51`.
  - `#pragma target monster golem` — The AI script for `MONSTER_GOLEM` (`e33a`).
  - `#pragma target script mainchr/c01_max.c` — A specific script path (`*` and `?` wildcards allowed).
  - `#pragma target library lib/map/base_town_villagers_v1.c` — Every script that includes a shared library.
- **`#pragma override`**: Replaces a function of the same name in the target script, including functions the script gets from an `#include "lib/..."` file. Call `original(...)` inside it to run the replaced function.
- **`#pragma override NATIVE_NAME`**: Intercepts every call the target script makes to an engine native (such as `place_monster` or `play_se`).
- **`#pragma every_frame`**: Calls a `void func(void)` function before every `wait;` in the target script.

## Message text formatting codes

Strings passed to `show_message` or `modkit_say` can include these tags:

| Tag | Displays |
| --- | --- |
| `\n` | Line break |
| `<page>` | Page break (waits for button press before showing the next page) |
| `(O)` `(X)` `(A)` `(#)` | Circle, Cross, Triangle, and Square button icons |
| `[l1]` `[r1]` `[l2]` `[r2]` `[start]` `[select]` | Shoulder, Start, and Select button icons |
| `[Number1]` … `[Number16]` | Integer set before `show_message` with `set_message_value(window, slot, val)` |
| `[heart]` `[hp]` `[mp]` `[weapon]` `[fish]` | Status and item icons |

## Editor setup (VS Code / `clangd`)

`dc2tk setup` writes `compile_flags.txt` in `extracted/scripts/`. Open `extracted/scripts/` in VS Code with the **clangd** extension installed for autocomplete, type checking, and hover documentation across all natives and constants.

For a mod in `mods/<name>/`, `dc2tk mod override` (or `dc2tk mod header extracted/scripts <name>`) generates `compile_commands.json` inside the mod folder so `clangd` resolves all functions and globals from the target script.
